# Model cards

Every training run writes a model card and attaches it to MLflow as `model_card.md`:

| Artifact | Location |
| --- | --- |
| Card for the run | MLflow run → Artifacts → `model_card.md` |
| Checkpoint | `artifacts/models/<name>.pt` + `<name>.json` sidecar |
| Local metrics | `metrics/<experiment>.json` |
| Plots | `artifacts/figures/<experiment>_*.png` |
| Registry entry | `mlflow.registry_model_name` from the config |

The card is generated by `src/medmlops/report.py` and covers:

* task and architecture;
* dataset and split sizes;
* MLflow run id and git commit;
* hardware used;
* held-out test metrics (Dice/IoU for segmentation, accuracy/AUC/sensitivity/specificity/ECE for
  classification);
* operating threshold for segmentation;
* intended use, out-of-scope limitations and the “not a medical device” disclaimer;
* reproducibility instructions.

## Retrieving the champion card

```bash
curl -s localhost:8000/api/models/champion/isic-lesion-unet | jq
```

The response includes the champion version, run id, test metrics and the card description stored on
the model version. For the full text, open the run in the MLflow UI and download
`model_card.md` from its artifacts.

## Governance notes

* Cards are regenerated on every run, so metric tables always reflect the exact checkpoint that was
  registered.
* Never edit a generated card in place — change the training/evaluation code so the next run records
  the corrected information.
* The cards are deliberately explicit about single-dataset evaluation and annotation noise; keep
  that language when copying excerpts into reports or slides.
